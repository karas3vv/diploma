# Влияние обновления графа межканальных связей на обнаружение структурных изменений во временных рядах

Дипломная работа четвёртого курса. В ней сравниваются два способа построения
графа связей между каналами временного ряда: сохранить граф, полученный на
обучающих данных, или обновлять его по мере поступления новых наблюдений.

Нужно выяснить, когда обновление помогает обнаруживать изменения связей,
а когда приводит к пропускам, ложным тревогам или увеличивает затраты на обработку.
Главный вопрос — как результат зависит от длительности изменённого режима,
длины окна оценки связей и частоты перестроения графа. Также будут исследоваться
сила изменения, шум и зависимость наблюдений от прошлого.

## Что сравнивается

Основная модель — **GATv2**. Вершины графа соответствуют каналам временного ряда,
а рёбра задают, между какими каналами модель может передавать информацию.

| Вариант | Как строится граф |
|---|---|
| Фиксированный граф | Связи оцениваются по обучающим данным, затем набор рёбер сохраняется |
| Обновляемый граф | Те же правила оценки и отбора связей применяются к последним наблюдениям; граф перестраивается через заданное число шагов |

У моделей будут одинаковые входные признаки, блок обработки временной истории,
выходной блок и обучающая задача. Для отбора рёбер используются общие правила
и одинаковое ограничение на их число. На настройку обоих вариантов отводится
сопоставимый объём вычислений.

Каждая модель обучается с тем способом построения графа, который будет
использоваться при тестировании. Поэтому обученные веса двух моделей могут
различаться. Во время тестирования веса не меняются: пересчёт рёбер
не сопровождается дообучением нейросети.

Коэффициенты внимания в GATv2 могут меняться и при фиксированном наборе рёбер.
Это свойство механизма внимания следует отличать от обновления структуры графа
и от обработки временной истории.

Дополнительно можно проверить одну обученную модель в двух условиях:
продолжать обновление графа или зафиксировать его до тестовых событий.
Такой опыт поможет рассмотреть влияние перестроения при одинаковых весах.
При этом фиксация графа меняет условия применения модели, поэтому результаты
этой проверки будут разбираться отдельно от основного сравнения.

## Первый эксперимент

Чтобы использовать GATv2 для обнаружения смен, нужно определить, чему обучается
модель и как по её выходу принимается решение о тревоге:

```text
Доступные наблюдения → модель → оценка изменения → порог → тревога
```

Перед реализацией нужно выбрать:

| Что выбрать | Что требуется описать |
|---|---|
| Обучающую задачу | Прогноз следующего значения или маскированное восстановление; сначала достаточно одного варианта |
| Генератор | Как формируются наблюдения, какие зависимости меняются и что происходит на границах режимов |
| Обучающие данные | Один нормальный режим, несколько допустимых режимов или размеченные смены |
| Вход и ответ модели | Какие измерения доступны, где заканчивается окно и какое значение нужно предсказать |
| Обучение | Обработка временной истории, выходной блок, функция потерь и нормализация |
| Граф | Оценка связей, длина окна, период обновления, число соседей, направление рёбер, симметризация и петли |
| Сигнал обнаружения | Формула, нормировка, объединение оценок каналов и участок истории для сравнения |
| Событие | Момент начала смены или весь интервал; считается ли возврат отдельной сменой |
| Тревоги | Порог, объединение соседних срабатываний, обработка повторных тревог и сопоставление с событиями |
| Ожидаемое различие | Какой эффект проверяется и какое улучшение будет считаться практически значимым |

### Чему обучать модель

Пока рассматриваются два варианта.

- **Прогнозирование.** По последним наблюдениям предсказывать следующий вектор
  значений и использовать ошибку прогноза для обнаружения смены. Для генерации
  можно начать с устойчивого VAR(1): `x_t = B_r x_(t-1) + ε_t`, где `r` — режим.
  Нужно проверить устойчивость, стационарные ковариации и поведение на переходе
  между режимами. Изменение `B_r` само по себе не гарантирует сохранения
  распределений отдельных каналов. Одновременная корреляция и влияние прошлого
  одного канала на другой описывают разные зависимости; способ построения рёбер
  должен соответствовать выбранной задаче.
- **Маскированное восстановление.** Скрывать значение канала и восстанавливать
  его по остальным каналам. Один из вариантов данных — гауссовские векторы с меняющейся
  положительно определённой корреляционной матрицей и неизменными средними
  и дисперсиями. Скрытое значение и его копии исключаются как из признаков,
  так и из данных для оценки графа того же примера.

Выбор генератора связан с задачей обучения. Например, если векторы независимы
во времени и имеют нулевое среднее, оптимальный прогноз по прошлому остаётся
нулевым. При неизменных дисперсиях перестройка одновременных корреляций
не меняет ожидаемую суммарную квадратичную ошибку этого прогноза, хотя может
менять распределение ошибки. Поэтому такой пример нельзя без дополнительной
проверки использовать для исследования детектора по ошибке прогноза.

### Как строить граф

Первый вариант — оценивать модуль корреляции Пирсона и выбирать `top-k`
соседей для каждого канала. Знак корреляции сохраняется отдельно для анализа.
До эксперимента нужно решить, будут ли рёбра направленными, как выполнять
симметризацию, добавлять ли петли и что делать с одинаковыми оценками.
Ограничение на число рёбер задаётся с учётом этих правил.

Модуль корреляции не различает положительную и отрицательную связь одинаковой
силы. Кроме того, изменение силы связи может сохранить порядок соседей,
а значит, и набор рёбер при `top-k`.

Окно признаков и окно оценки графа задаются отдельно. Для каждого момента
нужно указать, какие наблюдения доступны модели и оценщику связей. Будущие
значения и недоступные ответы модели не участвуют в построении графа.
Также нужно определить, в какой момент фиксируется статический граф
и какая история используется для его оценки.

### Как выдавать тревогу

В основном сравнении сигнал обнаружения вычисляется одинаково для обоих
вариантов графа. Для начала можно использовать среднюю квадратичную ошибку
прогноза или восстановления, нормированную на число доступных целевых значений.
Точная формула выбирается до эксперимента.

Затем на одной обученной модели планируется сравнить три способа обнаружения:

- **По ошибке модели (residual-only)** — использовать ошибку прогноза
  или восстановления.
- **По вниманию (structural-only)** — оценивать изменение распределений
  внимания относительно выбранного окна из доступного прошлого. Один из
  вариантов — дивергенция Дженсена — Шеннона.
- **По двум сигналам (joint)** — объединять ошибку и изменение внимания.
  Нормировка и параметры объединения выбираются по обучающим
  и валидационным данным.

Для сравнения внимания нужно определить, как объединять головы, сопоставлять
соседей до и после обновления, дополнять отсутствующие рёбра нулями
и нормировать распределения. Проверка с фиксированным набором рёбер поможет
понять, какая часть сигнала связана с изменением внимания, а какая —
с перестройкой самого графа.

Расстояние между последовательными копиями фиксированной матрицы графа всегда
равно нулю. Поэтому оно не может быть единственным сигналом для сравнения
фиксированного и обновляемого вариантов.

## Данные

Основные эксперименты будут проводиться на синтетических рядах с известными
моментами смен и заданными зависимостями.

| Сценарий | Что меняется | Что проверяется |
|---|---|---|
| Без смен | Зависимости сохраняются | Как часто перестраиваются рёбра и возникают ложные тревоги |
| Устойчивая смена | Система переходит к новым зависимостям | Когда обновление помогает обнаружить смену и уменьшить задержку |
| Временная смена | Зависимости меняются на ограниченное время, затем возвращаются к исходным | Успевает ли граф перестроиться и сохраняется ли сигнал о событии |
| Изменение значений | Меняются уровни или масштабы при сохранении выбранных целевых связей | Насколько детектор реагирует на изменения отдельных каналов |

Для сценария изменения только связей нужно проверить, что распределения
отдельных каналов действительно сохранились. Генератор должен сохранять
параметры, начальные значения (seeds) генераторов случайных чисел, моменты смен
и истинные зависимости выбранного типа.

Шум, сила смены и автокорреляция исследуются отдельно. Добавление независимого
шума само может ослабить наблюдаемую корреляцию. Для прогнозирования зависимость
от прошлого должна присутствовать уже в основном генераторе; при восстановлении
её влияние можно проверить отдельным опытом.

После синтетических экспериментов планируется проверка на
[SMD — Server Machine Dataset](https://github.com/NetManAIOps/OmniAnomaly).
Ряды и условия эксперимента выбираются до оценки тестовых результатов.
Метки SMD обозначают аномалии. Они позволят оценить обнаружение событий,
но не подтверждают, какие именно связи изменились и была ли структурная смена.

## С чем сравнить GATv2

Для первого эксперимента нужны два дополнительных метода:

- **Статистический детектор.** Использовать тот же способ оценки связей
  и расстояние Фробениуса между текущей корреляционной матрицей и опорной.
  Опорной может быть матрица по обучающим данным или по выбранной истории,
  доступной к текущему моменту. Текущая матрица пересчитывается по наблюдениям.
  Способ выбора опоры и порога определяется до тестирования.
- **Неграфовая модель.** GRU или TCN с той же доступной историей и той же
  целевой переменной. По возможности сохранить общий блок обработки времени.

После основного сравнения можно повторить опыт на исходном GAT и проверить,
сохраняется ли результат при смене архитектуры.

Другие модели и изменения — GATv2 + GRU, TGAT, MTAD-GAT, GDN, сглаживание графа,
CUSUM и дополнительные оценщики связей — можно рассмотреть после основных
экспериментов. Для каждого такого опыта нужен отдельный вопрос.
GATv2 + GRU и TGAT — разные модели. Для использования TGAT потребуется
определить, какие события взаимодействия соответствуют измерениям каналов.

## Как проводить сравнение

- Разделить данные на обучение, валидацию и тест до формирования окон.
  Каждый сгенерированный ряд используется только в одной выборке.
  Параметры нормализации оцениваются по обучающим данным.
- Подобрать пороги на валидации под заданную частоту ложных тревог.
  На тесте измерить фактическую частоту: **FAR — число ложных событий тревоги
  на единицу времени**. Тестовая разметка не используется для настройки порога.
- Оценивать точность, полноту и F1 по событиям. Задержку показывать вместе
  с полнотой и числом пропусков. Правила объединения тревог и их сопоставления
  с событиями задать заранее.
- Провести не менее пяти запусков обучения. Использовать отдельные seeds
  для обучения и для генерации тестовых рядов. Все методы сравнивать
  на одних и тех же тестовых траекториях. Для интервалов различий можно
  использовать парный bootstrap по независимым траекториям; перекрывающиеся
  окна не считаются независимыми наблюдениями.
- Проверить, что добавление будущих наблюдений не меняет уже вычисленные
  оценки и выданные тревоги.
- Измерять затраты на построение графа, работу модели и вычисление сигнала.
  Отдельно показывать 95-й процентиль времени обработки и задержку от смены
  до тревоги, включая ожидание следующего обновления графа.

В экспериментах нужно ответить на следующие вопросы:

| Вопрос | Что сравнить |
|---|---|
| При какой длительности смены помогает обновление? | Полноту и задержку при разных окнах и периодах обновления, с учётом фактической частоты ложных тревог на тесте |
| Может ли обновление ослабить сигнал о событии? | Число пропусков и длительность превышения порога при разных периодах перестроения |
| Приводят ли ошибки оценки связей к лишним тревогам? | Изменение рёбер, например `1 − Jaccard(E_t, E_(t-1))`, вместе с ложными тревогами; изменение рёбер само по себе ещё не означает ухудшения |
| Помогает ли сигнал по вниманию дополнить ошибку модели? | Residual-only, structural-only и joint, включая проверку с фиксированным набором рёбер |
| Сохраняется ли результат на другой архитектуре? | Фиксированный и обновляемый графы на GAT после основного сравнения GATv2 |

До итогового теста нужно определить, какое различие между методами будет
считаться практически значимым. Возможно, в части сценариев обновление
не даст заметного преимущества.

Для разбора результатов на одном графике нужно показать истинные моменты смен,
моменты обновления графа, изменения рёбер, ошибки модели, оценку по вниманию,
порог и тревоги. Это поможет понять, с чем связаны пропуски и ложные срабатывания.

Готовый файл — `text/diploma.pdf`. PDF и промежуточные файлы сборки не попадают в Git.

Для автоматической пересборки запустить `bash watch.sh` из корня репозитория.
Скрипту нужен `inotifywait`. Сборка также выполняется в папке `text/`.

### Оформление текста

- В русском тексте LaTeX тире записывается как `"---`, с пробелами по сторонам:
  `временной ряд "--- это последовательность наблюдений`. Так оно оформлено
  в исходнике диплома Ивана. Дефисы и математические знаки минуса используются
  по своему назначению.
- Существующие комментарии в исходниках сохраняются без изменений.
- Определения и объяснения пишутся прямо, без общих фраз и шаблонных оборотов.
  Ссылка ставится рядом с утверждением, которое она подтверждает:
  `При ретроспективном анализе алгоритму доступна вся запись~\cite{truong2020review}.`
- Фамилии авторов и названия работ нужны, когда обсуждается конкретный метод
  или результат. Для общего определения достаточно ссылки на источник.
